# SDK Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone Java SDK (`ao.bitubi.inference4j.sdk`) that loads a model, chats in one-shot calls and in
sessions, streams tokens as a cancellable `Stream<Token>`, embeds text, picks working types automatically or
manually, and fails with typed, actionable errors.

**Architecture:** A thin layer in `bitubi-inference-4j-core` over `AbstractModel`. `DefaultBi4j` owns one loaded model.
`Engine` (package-private) is the only class that calls `AbstractModel.generate`. It maps settings, stop
sequences, finish reasons, usage and JFR events. Sessions and streams are built on `Engine`. Everything public
is an interface, a record, an enum or a sealed exception.

**Tech Stack:** Java 25 (bytecode 21), JDK only (records, sealed types, `Stream`, virtual threads, `jdk.jfr`), JUnit 4
as in the existing tests. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-12-sdk-dx-design.md`

## Global Constraints

- JDK 25 builds and runs; bytecode stays 21 (`--release 21`), so no language feature newer than 21.
- No new Maven dependency. Logging through SLF4J (already in core). Events through `jdk.jfr`.
- Public API only in `ao.bitubi.inference4j.sdk`; everything else added by this plan is package-private there.
- Code, Javadoc, messages and docs in English. New files carry `conf/license-header-new`; files from Jlama that
  you modify get `Modifications Copyright 2026 Bitubi Solutions` under the original header.
- Defaults from the spec: `maxNewTokens` 512, `temperature` 0.7, persistent sessions, automatic working types.
- Commits: no `Co-Authored-By`, `Claude-Session` or "Generated with" lines. Commit straight to `main`.
- Build: `export JAVA_HOME=$HOME/.sdkman/candidates/java/25.0.3-amzn`, then `./mvnw -B ... package` (never `test`).
  Always exclude `-Dtest='!TestSample'` on full runs. `DistributedServiceTest` fails with HTTP 401 (gated model);
  that failure is known and not caused by this plan.
- Format with `./mvnw -B -q spotless:apply -pl <module>`. Spotless reformats files you did not touch, so restore
  those with `git checkout -- <file>` before committing.
- Tests that load a model use `tjake/Qwen2.5-0.5B-Instruct-JQ4` through
  `SafeTensorSupport.maybeDownloadModel("./models", ...)`. They live in `bitubi-inference-4j-tests`, package
  `ao.bitubi.inference4j.sdk`, and run without an env flag (CI caches the model).
- Known failures that already exist: `TestCorrectness.testNeoTokenizer`, `testPromptSupport2` and
  `testPromptSupportWithTools`.

## Review Focus

1. Any call on a `Bi4j` or `ChatSession` after `close()` must throw `IllegalStateException("... is closed")`. It
   must never reach freed KV pages, which crash or fail deep inside the engine. Covered in Tasks 4 and 6.
2. A stop sequence split across two tokens (for example `"\n\n"` produced as `"\n"` + `"\n"`) must still stop
   generation, and the stop text must not reach the response or the stream. Covered in Task 5.
3. `Bi4j.close()` while a stream is still open (not consumed, not closed) must return within a few seconds,
   cancel that generation, and leave no `.page` files. Covered in Task 7.
4. Invalid settings must fail when the `GenerationSettings` record is built, not inside the engine:
   `maxNewTokens <= 0`, `temperature < 0`, NaN temperature, or a null or empty stop string. Covered in Task 1.
5. An empty user message (`""`) must return a response without throwing. Covered in Task 5.

### Task 3: Working types and the memory estimate

**Files:**
- Create in `sdk/`: `WorkingTypes.java`, `ModelInspection.java`, `MemoryEstimate.java` and `MemoryBudget.java`
  (all package-private)
- Test: `bitubi-inference-4j-core/src/test/java/ao/bitubi/inference4j/sdk/WorkingTypesTest.java` and
  `MemoryBudgetTest.java`; `bitubi-inference-4j-tests/.../sdk/ModelInspectionTest.java`

**Interfaces:**
- Produces:
  - `record WorkingTypes(DType memory, DType activations)`:
    - `static WorkingTypes automatic(DType weights)` follows the spec table: Q4 → (F32, I8); Q8_0, BF16, F16 and
      F32 → (F32, F32). Q8_0 GGUF weights show up as `DType.I8` in the engine.
    - `static List<String> risks(WorkingTypes chosen, DType weights, MemoryEstimate e, MemoryBudget.Available a)`
      returns one English sentence per risk: "does not fit" (from `MemoryBudget.problems`), "slower than
      automatic (…)" when the activations differ from `automatic`, and "lower precision" for I8 activations on
      non-Q4 weights.
    - `static boolean hasKernel(WorkingTypes t, DType weights)`. The memory type must be F32 or BF16. The
      activations must be F32, or I8 when the weights are Q4.
  - `record ModelInspection(Path root, DType weights, long weightBytes, boolean gguf, ModelSupport.ModelType type,
    int layers, int kvLength, int maxContext)` with `static ModelInspection of(Path modelRoot)`:
    - For safetensors: `SafeTensorSupport.detectModel(config.json)`, then `readTensorInfoMap` on each shard header.
      The weight type is the most common `DType` by byte count, and `weightBytes` is the sum of the shard sizes.
    - For GGUF: the same values come from `GgufFile`.
    - The layer and KV dimensions come from `Config` (`numberOfLayers`, `kvLength`, `contextLength`).
  - `record MemoryEstimate(long weightBytes, long directBytes, long kvBytes)`:
    - `static MemoryEstimate of(ModelInspection m, WorkingTypes t, int contextLength)`.
    - `kvBytes = 2L * layers * contextLength * kvLength * t.memory().size()`.
    - `directBytes = 2 * weightBytes` for F16 GGUF (widened to F32), otherwise 0.
  - `final class MemoryBudget`:
    - `record Available(long physicalBytes, long maxDirectBytes, long diskBytes)` and
      `static Available measure(Path workDir)`. Physical memory comes from
      `com.sun.management.OperatingSystemMXBean.getTotalMemorySize()`. `MaxDirectMemorySize` comes from
      `HotSpotDiagnosticMXBean`; 0 means `Runtime.maxMemory()`. Disk comes from
      `Files.getFileStore(workDir).getUsableSpace()`.
    - `static List<String> problems(MemoryEstimate e, Available a)` returns one sentence per resource that does
      not fit. Each sentence gives both numbers in GiB and the fix:
      - for physical memory, a smaller `contextLength` or a more quantized model;
      - for direct memory, `-XX:MaxDirectMemorySize=<estimate rounded up to whole GiB>g`;
      - for disk, the working directory and its free space.

### Task 5: One-shot chat through `Engine` (temporary sessions, stop sequences, usage, JFR)

**Files:**
- Create in `sdk/`: `Engine.java` (package-private), `ChatRequestBuilder.java` (public final),
  `PromptMapper.java` (package-private) and `GenerationEvent.java` (`@Name("ao.bitubi.inference4j.Generation")`)
- Test: `bitubi-inference-4j-tests/.../sdk/OneShotChatTest.java`; `bitubi-inference-4j-core/src/test/.../sdk/StopMatcherTest.java`

**Interfaces:**
- Consumes: `DefaultBi4j.model()`, `GenerationSettings`, `ChatRequest`, `Message`.
- Produces:
  - `ChatResponse Engine.run(UUID session, PromptContext prompt, GenerationSettings s, Consumer<Token> onToken)`.
    It calls `model.generate(session, prompt, s.temperature(), s.maxNewTokens(), callback)`, feeds the text
    through a `StopMatcher`, and maps `Generator.FinishReason` as follows: `STOP_TOKEN` → `STOP`,
    `MAX_TOKENS` → `LENGTH`, `CANCELLED` → `CANCELLED` (or `STOP_SEQUENCE` when the matcher fired), and
    `ERROR` → `IllegalStateException`. It fills `Usage` and commits a `GenerationEvent`.
  - `static final class StopMatcher` inside `Engine`, built with `StopMatcher(List<String> stops)`.
    `String accept(String piece)` returns the text that is safe to emit now. It holds back any suffix that could
    still be the start of a stop string. `boolean stopped()` and `String flush()` (for the end of generation) go
    with it. When a stop matches, it sets `stopped` and interrupts the current thread, so the engine ends with
    `CANCELLED` at the next token.
  - `static PromptContext PromptMapper.toPrompt(Optional<PromptSupport> ps, List<Message> messages, boolean continuation)`:
    - It maps `SYSTEM`, `USER` and `ASSISTANT` to `addSystemMessage`, `addUserMessage` and `addAssistantMessage`.
    - With `continuation`, it calls `stripPreamble()`.
    - Without prompt support, it joins `Message.text()` with blank lines into `PromptContext.of(...)`.
    - Before anything else, it throws `UnsupportedInputException` for any message whose `modalities()` are not
      inside `capabilities().inputs()`. The message reads: "this model reads TEXT only; got IMAGE".
  - `ChatRequestBuilder`, returned by `Bi4j.chat()`:
    - `system(String)`, `user(String)`, `user(Part...)`, `assistant(String)`, `maxNewTokens(int)`,
      `temperature(float)` and `stop(String...)`;
    - `ChatRequest request()`, `ChatResponse generate()` and `Stream<Token> stream()` (Task 7).
  - `Bi4j.generate(ChatRequest)` runs on a fresh `UUID`. In `finally`, it calls `model.releaseSession(uuid)`
    (temporary session).
