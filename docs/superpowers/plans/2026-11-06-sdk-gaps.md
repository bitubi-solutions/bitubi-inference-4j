# SDK gaps closed for the server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Add the seven things the server design found missing from the SDK (restore, per-call settings, a `Generation` handle with result and cross-thread cancel, context accounting, load progress, model info).

**Architecture:** All in `ao.bitubi.inference4j.sdk` of `bitubi-inference-4j-core`, on the existing `DefaultChatSession`, `TokenStream` and `DefaultBi4j`. One engine addition: `AbstractModel.prefill`.

**Tech Stack:** Java 25 (bytecode 21), JDK only, JUnit 4, the Qwen2.5-0.5B JQ4 test model.

**Spec:** `docs/superpowers/specs/2026-10-12-sdk-dx-design.md`, section 13 (decisions and signatures).

## Global Constraints

- Same as `2026-11-05-sdk-phase-1.md`: bytecode 21, no new dependency, English, new files carry `conf/license-header-new`, no `Co-Authored-By`/`Claude-Session`/"Generated with" lines, commit to `main`, build with `./mvnw -B ... package` (never `test`), restore files that spotless reformats and that you did not touch.
- Nothing that exists changes behavior: `send(String)`, `stream(String)`, `Bi4j.stream(ChatRequest)` keep their contracts.

## Review Focus

1. `restore` on a session that already answered, on a temporary session, or with a history that does not fit: each fails with the exception named in the spec and leaves the session as it was.
2. `Generation.cancel()` before the first read, after the end, twice, and while the reader is blocked: never hangs, never throws, `result()` is consistent.
3. `contextTokens()` after a cancelled generation and after `restore` equals the engine's position.
4. A `LoadProgress` callback that throws must not break `build()` or leave the work directory behind.
5. A `GenerationSettings` per call must not leak into the session defaults.
